# АрендаЛог — журнал аренды с доказуемой хронологией

Android-приложение для арендатора: фиксирует дефекты, улучшения, платежи, показания счётчиков,
приёмку и сдачу жилья — с такой привязкой ко времени, чтобы записи можно было предъявить в суде.

**Скачать:** [страница с кнопкой](https://luckyvoron-tech.github.io/arendalog/) ·
[прямая ссылка на APK](https://github.com/luckyvoron-tech/arendalog/releases/latest/download/ArendaLog.apk) ·
[выпуски](https://github.com/luckyvoron-tech/arendalog/releases)

**Обновления:** приложение само сверяется с последним релизом на GitHub и показывает баннер
«Доступна версия N» — одно нажатие, и скачивается новый APK. Данные при обновлении сохраняются.

Собрано из реального спора с арендодателем: залог не вернули, улучшения не оплатили, а доказательства
приходилось собирать постфактум из переписок, чеков и фотографий.

**APK:** [`dist/ArendaLog-1.0.apk`](dist/ArendaLog-1.0.apk) · версия 1.0.1 · minSdk 24 (Android 7+), targetSdk 35

## 1. Идея и её правовая рамка

### Что приложение доказывает

| Механизм | Что даёт | Сила в суде |
|---|---|---|
| **Хеш-цепочка** (каждое событие содержит хеш предыдущего) | нельзя незаметно изменить или удалить запись — цепочка рвётся | высокая: проверяется программно за секунды |
| **Электронная подпись ECDSA P-256** ключом устройства | автором записи является конкретное устройство; ключ не экспортируется | высокая при идентификации владельца телефона |
| **Метка времени RFC 3161** (независимый сервер времени) | третья сторона подтверждает: этот хеш существовал в момент T | очень высокая: не зависит от часов телефона |
| **Сверка с временем сервера** | ловит перевод часов назад (`clockWarn`) | средняя, но закрывает главный довод «вы подделали дату» |
| **Пакет доказательств** (ZIP: отчёт, JSON, фото, манифест SHA-256, токены .tsr) | всё проверяемо экспертом и нотариусом | высокая в связке с нотариальным осмотром |

### Чего приложение не делает (честно)

- Не делает доказательства «неоспоримыми»: суд оценивает их по внутреннему убеждению (ст. 67 ГПК РФ),
  заранее установленной силы нет ни у одного доказательства.
- Без интернета метка времени не ставится: остаётся время телефона + хеш-цепочка. Это слабее — событие
  уходит в очередь и «догоняет» метку позже (тогда TSA подтвердит, что запись существовала не позже этого момента).
- Не заменяет нотариальный осмотр. Но делает его дешёвым: нотариусу достаточно открыть ZIP и сверить хеши.

### Как усилить позицию в реальном споре

1. Ставьте метку времени сразу (приложение делает это само при сохранении).
2. Фиксируйте приёмку **при заселении** — это защита от «вы всё сломали» при выезде.
3. Просите арендодателя подтверждать события в приложении (режим просмотра) или хотя бы в переписке.
4. Перед судом — нотариальный осмотр переписки и журнала либо ходатайство об осмотре доказательств
   (ст. 58, 183 ГПК РФ).

## 2. Что уже работает (v1.0)

**Объект и участники**
- **Зоны и комнаты настраиваются под объект**: добавить, переименовать, описать, удалить; у каждой зоны свой
  список пунктов для приёмки. Шаблоны: «Дом», «Квартира», «Студия», «Дом с участком», «Пустой список».
  Нетиповые зоны (мангальная, столовая на улице, второй санузел, лестница, кладовая) добавляются вручную.
- **Список проживающих** с ролями: арендатор, супруг(а), ребёнок, родственник, друг, арендодатель, другое.
  Список попадает в акт приёмки и в отчёт.

**Журнал**
- 7 типов записей: проблема, улучшение, **чек**, платёж, показания счётчика, уведомление, заметка.
- У каждого: время, описание, место (комната), критичность, сумма, контрагент, фотографии и документы.
- Фотографии сжимаются до 1600 px; чеки и счета принимаются как PDF и сохраняются с SHA-256.
- Фильтры по типу, цветовая маркировка, просмотр деталей с хешем, подписью и токеном TSA.

**Приёмка и сдача**
- Чек-лист из 8 зон (кухня, гостиная, спальни, санузел, прихожая, двор, коммуникации) — около 50 пунктов.
- По каждому пункту: норма / дефект / отсутствует + замечание.
- Акт подписывается и хешируется, попадает в журнал отдельным событием.

**Отчёт и экспорт**
- Печатный отчёт (A4) для суда: таблица событий, время устройства и метка TSA, фото с хешами, корень цепочки,
  отпечаток ключа, блок «как проверить», поля для подписей сторон.
- Отдельный раздел **«Чеки и подтверждающие документы»** с итоговой суммой и SHA-256 каждого файла.
- Печать в PDF через системный диалог Android.
- **Пакет доказательств .zip**: `report.html`, `journal.json`, `manifest.json` (SHA-256 каждого файла),
  `photos/`, `docs/` (чеки и PDF), `timestamps/*.tsr`, `verify.html`, `README.txt` с инструкцией проверки.
- **Верификатор `verify.html`** — автономная страница (внутри пакета и в приложении): перетащили архив →
  проверены хеши файлов, цепочка, подписи и отпечатки меток времени. Работает без интернета и без приложения.
- **Резервная копия .alog** — перенос журнала на другое устройство.
- **Приглашение арендодателю .alog** — открывается в режиме «только просмотр».

**Договор и передача записей**
- **Договор аренды** хранится в приложении: фото страниц или PDF, открыть, показать, сохранить в «Загрузки»
  и отправить кому угодно. Попадает в копию и в пакет доказательств.
- Арендодателю журнал передаётся файлом: «Приглашение арендодателю» (открывается в приложении) или
  PDF-отчёт. Сервер не нужен.
- Работает полностью офлайн; единственный сетевой запрос — метка времени (и её можно отложить).

**Прочее**
- Полностью офлайн (кроме метки времени), без серверов и регистрации.
- PIN-код, режим просмотра, удаление данных.
- Проверка целостности цепочки в один тап, индикатор состояния.
- Ключ подписи создаётся на устройстве и не может быть извлечён.

## 3. Дополнительные опции (что добавить дальше)

**Юридически сильные (приоритет 1)**
1. **Второй ключ на подпись арендодателя.** Акт с двумя подписями (арендатор + арендодатель) весит несравнимо
   больше. Реализуется как «подписать на моём телефоне» — арендодатель вводит код приглашения и подписывает своей парой ключей.
2. ~~**Верификатор для третьих лиц.**~~ **Сделано в 1.0:** `verify.html` в пакете — перетащили `.zip`,
   получили вердикт «пакет подлинный» либо список расхождений, без установки приложения и без сети.
3. **Фиксация показаний счётчиков с фотографией и расчётом** (тариф × показания, история, напоминание 20–25 числа).
4. **Уведомления с доказательством отправки**: шаблоны «не продлеваю», «уведомляю о выезде», «залог к возврату»,
   отправка через системный share с сохранением текста и времени в журнал.
5. **Реестр залога и удержаний**: залог, что удержано, основания, сроки возврата, автоматический расчёт
   «сколько должны вернуть».

**Практичные (приоритет 2)**
6. **Несколько объектов** (квартира, дача, гараж) с переключением.
7. **Напоминания**: окончание договора, передача показаний, платёж, срок возврата залога.
8. **Голосовые заметки** с расшифровкой на устройстве (whisper.cpp) — быстро фиксировать на месте.
9. **Шаблоны чек-листов** под типовые квартиры и дома, редактирование списка комнат.
10. **Сравнение «при заселении / при выезде»** — автоматический отчёт «что изменилось», лучший аргумент по залогу.
11. **Карта и геометка** (опционально, с предупреждением о приватности).
12. **Импорт переписок** (Telegram/WhatsApp экспорт) с привязкой к событиям.

**Технические (приоритет 3)**
13. **Шифрование локальной базы** (SQLCipher-аналог для WebView невозможен — потребуется нативный слой).
14. **QR-код события** для быстрой проверки третьим лицом.
15. **iOS**: то же веб-ядро оборачивается Capacitor'ом, меняется только нативная оболочка.
16. **Автоподпись пачкой** и пакетная отправка меток времени при появлении сети.
17. **Автоматическая копия в облако** (сейчас копия — файлом, по кнопке и с напоминанием).

> Совместный доступ через сервер сознательно не делается: основной сценарий — офлайн на одном телефоне,
> а арендодателю передаётся файл. Код сервера остаётся в истории репозитория, если понадобится позже.

## 4. Как устроена привязка ко времени

Четыре независимых уровня:

1. **Локальное время устройства** — фиксируется в момент сохранения (`tsDevice`).
2. **Хеш-цепочка** — `hash = SHA-256(canonical(событие) + prevHash)`. Любое изменение текста, суммы,
   списка фото или порядка событий ломает цепочку.
3. **Электронная подпись** — ECDSA P-256 ключом, созданным в хранилище устройства с флагом `extractable: false`.
   Ключ невозможно выгрузить, поэтому подпись нельзя подделать на другом устройстве.
4. **Метка времени RFC 3161** — на хеш события запрашивается токен у независимого сервера (по умолчанию
   `freetsa.org/tsr`). Токен хранится в событии и в пакете доказательств; он подтверждает, что хеш существовал
   в указанный момент. Запрос идёт через нативный мост — это обходит CORS браузера.

Дополнительно: при сохранении приложение сверяет время с сервером (`Date` от независимого хоста). Если часы
переведены назад больше чем на 2 минуты, событие помечается флагом `clockWarn`.

Проверить всё можно командой: `node tools/test_core.cjs` — тесты подменяют текст, удаляют и переставляют
события и показывают, что цепочка это ловит.

## 5. Архитектура

```
app/                     веб-ядро (без сборки и зависимостей)
  index.html             разметка всех экранов
  app.css                тёмная мобильная тема
  verify.html            автономный верификатор пакета (без сети и зависимостей)
  js/core.js             утилиты, IndexedDB, криптография, ASN.1/TSA, ZIP
  js/ui.js               экраны, формы, зоны, проживающие, отчёт, экспорт/импорт
  js/main.js             запуск, проверка окружения, PIN
  js/verifier-data.js    генерируется при сборке: копия verify.html для вложения в ZIP


android/
  AndroidManifest.xml    minSdk 24, targetSdk 35, INTERNET/VIBRATE
  src/ru/arendalog/app/MainActivity.java
                         WebView + мост: TSA-запросы, время сервера, сохранение файлов,
                         печать в PDF, вибрация, выбор фото/камера
  res/                   иконки, тема, строки

tools/
  build.py               сборка APK: aapt2 → javac → d8 → zipalign → apksigner (+ встраивание верификатора)
  serve.py               локальный сервер для проверки на ПК (статика + прокси TSA)
  test_core.cjs          19 тестов криптоядра и цепочки
  e2e.cjs                58 сквозных тестов в headless Chrome через CDP
  test_verify.cjs        7 тестов верификатора: подлинный пакет, подмена файла, подмена содержимого
  check_ui.py            сверка id разметки и ссылок из JS
  make_icons.py          генерация иконок
  unpack.py              распаковка тулчейна

dist/
  ArendaLog-1.0.apk      готовый установочный файл
  arendalog-release-key.keystore   КЛЮЧ ПОДПИСИ — сохраните, без него обновления не встанут
```

**Почему WebView, а не Kotlin UI:** одно ядро для Android и будущего iOS, нулевые зависимости,
мгновенные правки без пересборки. Всё, что нужно от платформы (сеть без CORS, файлы, печать, камера),
вынесено в нативный мост из ~300 строк.

Данные хранятся в IndexedDB внутри WebView. Origin — `https://arendalog.local`, который нативный слой
отдаёт из assets: это даёт полноценный защищённый контекст (WebCrypto, IndexedDB) без сети.

## 6. Сборка

Требуется Windows, Python 3 и интернет для первого скачивания тулчейна (~300 МБ).

```powershell
# 1. тулчейн (JDK 17 + build-tools 34 + platform android-35) в C:\arendatools
python tools\unpack.py            # если архивы уже скачаны в tools\downloads
# или заново скачать:
#   (скачивание выполняет tools\setup_toolchain.py, но надёжнее — PowerShell:
#    Invoke-WebRequest для jdk17.zip, build-tools_r34-windows.zip, platform-35_r02.zip)

# 2. сборка
python tools\build.py

# 3. проверки
node tools\test_core.cjs
node tools\e2e.cjs
python tools\check_ui.py
```

Путь к тулчейну задан константой `TOOLS` в `tools/build.py` (`C:\arendatools`).

Сборка без Gradle: `aapt2 compile/link` → `javac` (API 35) → `d8 --min-api 24` → вставка `classes.dex` →
`zipalign -p 4` → `apksigner` (v1+v2). Подпись — самоподписанный ключ, для личной установки этого достаточно.

## 7. Установка на телефон

1. Перекиньте `dist/ArendaLog-1.0.apk` на телефон (кабель, облако, Telegram «себе»).
2. Откройте файл. Android спросит разрешение «Устанавливать из неизвестных источников» — разрешите
   для файлового менеджера или мессенджера.
3. При первом запуске заполните «Объект»: адрес, стороны, срок, залог.
4. Дальше — кнопка «+» на главном экране.

Приложение не требует аккаунта и не отправляет данные никуда, кроме запроса метки времени на сервер RFC 3161
(передаётся только хеш, без содержимого).

## 8. Ограничения версии 1.0

- Один объект на журнал (несколько объектов — в планах).
- Сервер не удаляет события (журнал append-only — это осознанно).
- Метка времени требует интернета; без него событие ждёт в очереди.
- Нет шифрования базы (защита — PIN и sandbox Android; на сервере — токены и TLS).
- Отчёт печатается системным диалогом Android; выбор «Сохранить как PDF» — там же.
- Ключ подписи привязан к устройству: при смене телефона старые подписи проверяются по сохранённому
  открытому ключу (он есть в `.alog` и в манифесте).

## 9. Проверено

```
node tools/test_core.cjs   → 19 из 19
node tools/e2e.cjs         → 58 из 58 (реальная метка времени freetsa.org получена)
node tools/test_verify.cjs → 7 из 7 (подлинный пакет, подмена файла, подмена содержимого)
python tools/check_ui.py   → все ссылки на элементы найдены
build.py                   → APK подписан, apksigner verify OK
```

Тесты закрывают: канонический JSON, SHA-256, создание ключа, подпись и её проверку, обнаружение подмены/
удаления/перестановки событий, структуру ASN.1 запроса RFC 3161, сборку ZIP, создание события через
интерфейс, чек с контрагентом, настройку зон и проживающих, чек-лист приёмки по своим зонам,
формирование отчёта, экспорт пакета и его проверку автономным верификатором (данные → ZIP → вердикт),
а также сервер: роли, приглашения, отказ в правах, идемпотентность, проверку хешей и SSE-поток.
